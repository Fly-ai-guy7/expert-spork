# Internationalization (Arabic / English)

EQUALISE is bilingual from day one. Egyptian legal practice is primarily Arabic, so Arabic is
treated as a first-class citizen — not an afterthought.

## Backend

- **Storage**: every content-bearing table has side-by-side `text_ar` + `text_en` (or
  `title_ar`/`title_en`) columns. No translation table — keeping the schema flat is the
  scaffold's choice. Move to a normalized translations table when scale demands.
- **Lang enum**: `app/i18n.py` exposes `Lang.AR` / `Lang.EN`. `pick(text_ar, text_en, lang)`
  returns the right one with fallback.
- **Prompts**: agents include both columns in their structured output schemas, so the LLM
  produces both languages in one call. (Auto-translation is deferred; right now the LLM does
  best-effort bilingual emission.)
- **Statute corpus**: all 8 statute files ship with both `text_ar` and `text_en`. The Arabic
  is treated as the controlling original.

## Frontend

- **i18next**: `frontend/src/i18n/{en,ar}.json` hold UI strings.
- **Language toggle**: `LangToggle` calls `i18n.changeLanguage(lng)` which also flips
  `document.documentElement.dir = "rtl"` when Arabic. See `frontend/src/i18n/index.ts:14`.
- **Tailwind RTL**: the `index.css` has a `html[dir="rtl"]` selector that swaps the font to
  Noto Naskh Arabic / Amiri. Tailwind v3 utilities are direction-agnostic; flex/grid
  visually flip with `dir="rtl"`.
- **Content rendering**: components read `i18n.language` and pick the right column:
  ```tsx
  const content = i18n.language === "ar" ? a.content_ar : a.content_en;
  const fallback = i18n.language === "ar" ? a.content_en : a.content_ar;
  ```

## PDF

- WeasyPrint renders RTL via `dir="rtl"` and the right font family.
- The bundled Arabic font is **Noto Naskh Arabic** (installed in `backend/Dockerfile`).
- Templates live at `backend/app/reports/templates/report.{ar,en}.html.j2` and
  `coaching.{ar,en}.html.j2`. Pick by `case.language_primary`.
- The disclaimer is rendered at the top and bottom of every page footer via
  `@page { @bottom-center }` in `reports/styles.css`.

## Deferred i18n work

- Auto-translation: if a case is `language_primary="en"` and an agent doesn't emit Arabic, the
  Arabic column stays empty. A `translate(text, target_lang)` service is a future addition.
- Locale-aware date / number formatting in the UI (currently English-style throughout).
- Localized statute search ranking (Arabic stemming via `unaccent` extension is already loaded
  in `infra/postgres/init.sql` but not yet plumbed through).
